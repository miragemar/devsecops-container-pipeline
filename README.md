# Secure Container Delivery Platform

DevSecOps-проєкт для збирання, аналізу, сканування та контролю випуску Docker-образів.

## Мета проєкту

Мета проєкту — створити систему безпечної доставки контейнерних образів, яка перевіряє їх перед допуском до релізу.

Платформа поєднуватиме сканування вразливостей, перевірку політик безпеки, генерацію SBOM, аналіз метаданих образу та автоматизовані перевірки в CI/CD.

## Запланована архітектура

1. **Збирання образу (Build)** — створення Docker-образу на основі вихідного коду застосунку.
2. **Аналіз образу (Inspect)** — отримання метаданих і визначення образу, який проходить перевірку.
3. **Сканування (Scan)** — використання Trivy для пошуку відомих вразливостей.
4. **Перевірка політики (Policy Evaluation)** — порівняння результатів сканування з правилами у `security/policy.yaml`.
5. **Генерація SBOM** — створення машинозчитуваного переліку компонентів програмного забезпечення в образі.
6. **Допуск до релізу (Promote)** — дозвіл на подальший випуск образу лише після проходження необхідних перевірок.
7. **Автоматизація (Automation)** — запуск процесу через GitHub Actions.

## Структура проєкту

```text
app/                     Тестовий застосунок
tests/                   Автоматизовані тести
security/policy.yaml     Конфігурація політики безпеки
security/scan-image.sh   Сканування контейнерних образів
scripts/inspect-image.sh Аналіз метаданих образу
scripts/generate-sbom.sh Генерація SBOM
scripts/promote-image.sh Перевірка допуску до релізу
reports/                 Згенеровані звіти безпеки
.github/workflows/       Автоматизація CI/CD
Dockerfile               Інструкції зі збирання контейнера
requirements.txt         Залежності застосунку
requirements-dev.txt     Залежності для розробки та тестування
```

## Механізми безпеки

Заплановані механізми захисту:

- Сканування вразливостей за допомогою Trivy.
- Налаштування допустимих рівнів критичності вразливостей.
- Автоматичне блокування релізу, якщо порушено політику безпеки.
- Генерація SBOM для контролю компонентів і залежностей програмного забезпечення.
- Контроль ідентичності образу, щоб зменшити ризик випуску образу, відмінного від того, який пройшов перевірку.

## Поточний стан розробки

**Етап:** структуру репозиторію створено.

Сканер безпеки, механізм перевірки політик, генерація SBOM, логіка допуску до релізу та CI/CD-процес ще не реалізовані.

## Технологічний стек

- Docker

- Інструменти генерації SBOM

## Призначення проєкту

Проєкт зосереджений на безпеці контейнерів і контролі ланцюга постачання програмного забезпечення, а не лише на збиранні та розгортанні застосунку.

Розробка відбуватиметься поступово. Для логіки перевірки політик безпеки передбачені автоматизовані тести, а кожен компонент матиме документацію з поясненням його призначення.
